# Design

## Context

See `proposal.md` for the motivation. The current state that shapes the approach:

- `packages/plugin-codex-subagent` declares `@openai/codex` `0.169.0` and vendors the upstream
  app-server adapter; the bundled version is a literal in `openspec/specs/codex-subagent/spec.md`.
- `packages/setup/defaults.yml` selects `gpt-6-astra` at `xhigh` for `reviewers.codex`; the setup
  patch, setup `package.json`, and vendored tree are generated by `pnpm gen`.
- The three review instructions live in `packages/plugin-workflows/assets/reviews/`; the workflows
  spec requires the shipped reviewer to be the strong model at `xhigh`.
- Codex `0.170.0` is npm `latest`; `0.169.1` has no `win32-x64` optional package, so it cannot be
  the pin. GPT-6.2 requires Codex `>=0.166` on a ChatGPT login.

## Goals / Non-Goals

**Goals:**

- Move the bundled CLI and the shipped reviewer default to the current stable pair.
- Keep the shipped reviewer the strong model at `xhigh`, as the workflows spec requires.
- Make the bundled review instructions return a verdict instead of stopping to ask.
- Keep docs, specs, generated output, tests, and the live acceptance in agreement.

**Non-Goals:**

- Changing the default to `gpt-6.2-sol` or lowering `reasoningEffort`.
- Changing Ponytail or working-principles, which instruct `deepseek-flash`.
- Reimplementing Codex-owned request mechanics (`developer` message, prompt caching, prefix edits).
- Rewriting the P0/P1 rubric, the focused re-review contract, or the provider row schema.

## Decisions

### D1: Pin `@openai/codex` `0.170.0`

`0.170.0` is the current stable release and has every platform package, including `win32-x64`.
`0.169.1` is unusable on Windows because its `win32-x64` optional dependency is missing
(`openai/codex#62123`). `pnpm-workspace.yaml` `minimumReleaseAgeExclude` names the exact version and
platform packages, so it moves in the same change; otherwise the release-age rule would reject the
fresh install.

Alternative: stay on `0.169.0`. Rejected because Codex `>=0.166` is what unlocks GPT-6.2 on a
ChatGPT login, `0.170.0` carries the Windows file-replacement and sandbox-permission fixes, and the
repository's convention is to track the latest verified stable release.

### D2: Keep `gpt-6.2-astra` as the shipped reviewer model

OpenAI's guide recommends Astra for the most demanding tasks and Sol for everyday work at lower
cost. The workflows spec requires the shipped reviewer to select the strong model at `xhigh` and
forbids the weaker model as the default. Astra is the strong model; Sol remains a profile override.
The provider passes the id through `thread/start` and does not validate it against the Codex
catalog.

### D3: Keep `reasoningEffort: xhigh`

The workflows spec mandates `xhigh` for the shipped reviewer. The guide's "start with `medium`" is
guidance for a new API integration, not for a long-running review contract, and it recommends higher
effort for persisting through final checks. Lowering the effort is a cost decision outside this
change.

### D4: Add one review-posture section, not a prompt rewrite

The guide's applicable model-facing advice for a headless reviewer is task completion: make
reasonable assumptions and keep working instead of stopping to ask. Each of the three instructions
gains one `## Review posture` section: decide the verdict, do not ask or wait, finish with the single
JSON block, and treat incomplete input as a finding only under the P0/P1 rubric.

Not adopted:

- "Be concise" — the guide says revisit such instructions for Astra, not add them; the output is one
  JSON block.
- "Skip new tests unless requested" — the repository's review contract requires a covering check;
  the repository rule wins.
- Writing-style and frontend-design patterns — they target user-facing prose and UI, not a verdict.
- API mechanics — Codex builds the Responses request; the prompt assets cannot control it.

### D5: No review-thread migration

The guide lists a model change among the events that drop reasoning items. The thread store keeps
only `{threadId, cwd, sandbox}` and the next resume passes the new model. The change lands at a
change boundary, so the one-time re-derivation is accepted; no record or thread is migrated or
deleted.

### D6: Verification and fallback

The unit tests assert the new pin, the generated default, and the prompt posture. The full gate
covers generation and the build diff. The live acceptance proves an authenticated turn on `0.170.0`
with `gpt-6.2-astra`. If the app-server protocol drifted, the change records the failure and falls
back to the verified `0.169.0` pin; `0.169.1` is never a fallback.

## Risks / Trade-offs

- **`0.170.0` shipped one day before this change** → the live acceptance is the gate; a protocol
  failure returns to the verified `0.169.0` pin.
- **Codex's bundled catalog may not list `gpt-6.2-astra`** → the id passes through and works on a
  ChatGPT login (`>=0.166`); an API-key login may log a fallback-metadata warning.
- **A model change on a resumed thread drops reasoning** → land at a change boundary and accept the
  one-time re-derivation; the store is scratch.
- **`pnpm gen` rewrites the vendored tree** → `pnpm build && git diff --exit-code` and
  `pnpm gen:check` catch drift.
- **Windows-only dependency breakage** → the platform package is verified on npm before the install;
  `0.169.1` is excluded by name in the design and the tasks.

## Migration Plan

1. Bump the dependency, workspace release-age exclusion, `NOTICE`, locale, README, docs, pinned
   test, and live acceptance.
2. Change the shipped default in `packages/setup/defaults.yml` and the setup-release expectation.
3. Add the review-posture section to the three instructions and the assets test.
4. Run `pnpm gen` after steps 1-3, so the vendored tree carries the bumped metadata, the new model,
   and the posture; then run the full gate and the live acceptance.

Rollback: pin `@openai/codex` `0.169.0` and `reviewers.codex.model` `gpt-6-astra`, regenerate, and
revert the prompt posture; no installed profile data or review records are migrated, so the previous
release remains installable.
