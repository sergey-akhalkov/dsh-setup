# Tasks

## 1. Package manifest and Git facts (lane 1, owns `packages/plugin-worktrees/package.json`, `packages/plugin-worktrees/cordis.fragment.yml`, `packages/plugin-worktrees/tsconfig.json`, `packages/plugin-worktrees/locale/**`, `packages/plugin-worktrees/icon.svg`, `packages/plugin-worktrees/src/host/git.ts`, `packages/plugin-worktrees/test/git.test.ts`)

- [ ] 1.1 Create `packages/plugin-worktrees` with the `plugin-rust`-shaped manifest, `cordis.fragment.yml`, `locale/en.json`, `icon.svg`, `tsconfig.json`, and empty Host/Client entry points; verify `pnpm install` links the package and `pnpm typecheck` accepts the project reference.
- [ ] 1.2 Implement the Host Git reader: parse `git worktree list --porcelain` blocks, and read per-worktree `status --porcelain`, `merge-base --is-ancestor`, `log --oneline <base>..<head>`, birth time, and last activity, with per-command timeout and bounded output; verify a test over a temporary repository returns the expected facts for the primary checkout, a merged worktree, and a dirty worktree.
- [ ] 1.3 Resolve the base branch (`main`, else the primary checkout's branch) and the Git common directory for deduplication; verify tests cover a repository without `main` and a workspace nested below the repository root.

## 2. Policy, sweep, and report (lane 2, owns `packages/plugin-worktrees/src/host/policy.ts`, `packages/plugin-worktrees/src/host/sweep.ts`, `packages/plugin-worktrees/src/host/report.ts`, `packages/plugin-worktrees/test/policy.test.ts`, `packages/plugin-worktrees/test/sweep.test.ts`, `packages/plugin-worktrees/test/report.test.ts`)

- [ ] 2.1 Implement the pure policy planner over worktree facts: derived status, `managed`/`all`/`off` scope, `staleDays` escalation, live-session/locked/DSH-owned/snapshot protection, and a reason for every decision; verify unit tests cover merged-and-clean, unmerged, dirty, merged-but-dirty, stalled, live-session, locked, DSH-owned, and manual worktrees.
- [ ] 2.2 Implement the sweep executor: sequential `git worktree remove` without `--force`, a re-evaluation of every eligibility condition (merge state, cleanliness, live-session working directories, lock state, protected paths) immediately before each removal, per-worktree timeout, and `failed` items carrying Git's message; verify tests assert that a worktree made dirty between plan and removal is kept, that a session starting to use a planned worktree skips its removal, and that a Git refusal leaves the row unchanged.
- [ ] 2.3 Implement the report store under `.dsh/worktrees/reports/<ISO>.json` with the `at`, `trigger`, `base`, `removed`, `kept`, and `failed` fields and retention of the last 14 files; verify tests assert the report shape, the retention prune, and that a report survives a new store instance.
- [ ] 2.4 Make a sweep's decision independent of report write failures and serialize sweeps per workspace; verify a test with a failing report write still removes the eligible worktree and reports the failure without retrying.

## 3. Host routes, config, and schedule (lane 3, owns `packages/plugin-worktrees/src/host/routes.ts`, `packages/plugin-worktrees/src/host/config.ts`, `packages/plugin-worktrees/src/host/schedule.ts`, `packages/plugin-worktrees/src/host/index.ts`, `packages/plugin-worktrees/test/routes.test.ts`, `packages/plugin-worktrees/test/schedule.test.ts`)

- [ ] 3.1 Register the Fetch routes `list`, `detail`, `reports`, `sweep`, and `remove` with workspace resolution from a live session id and inert registration when `connection.fetch`, `agents`, or `workingDirectory` is absent; verify route tests cover a missing session, an unknown worktree, a protected worktree, and a path outside the fresh inventory.
- [ ] 3.2 Implement delete re-validation and the unsafe-delete confirmation contract: the refusal payload carries a Host-computed fingerprint of the head, the commits outside the base branch, and the content digests of every changed, staged, and untracked file; the confirmed request must carry that fingerprint, and the Host recomputes it and refuses a mismatch with the fresh payload; `--force` is used only for a matching confirmed request. Verify tests assert that an unconfirmed unsafe delete removes nothing, that a changed fingerprint is refused with refreshed details (including a changed file content with the same path and head), and that a matching confirmed request removes the checkout and keeps the branch.
- [ ] 3.3 Add the config schema and defaults `staleDays: 7`, `sweepAt: "04:00"`, `autoRemove: "managed"`; verify the projected Config schema accepts the defaults and rejects an unknown `autoRemove` value.
- [ ] 3.4 Add the schedule: recompute the next local calendar occurrence of `sweepAt` after every sweep, move a nonexistent local time to the first valid local minute after it that day, use the first occurrence of a repeated local time, run the startup catch-up, and add an in-flight guard that returns "already running"; verify fake-clock tests assert the day boundary, the skipped-hour fallback, the repeated-hour first occurrence, and a repeated trigger while a sweep runs.

- [ ] 4.1 Register the tab type, the `sidebar://worktrees` address, the Start-page guide entry with a branch icon, and the `sidebar.right.pane.tab` body, gated on the right-sidebar services; verify the client module builds and the registration test asserts the tab definition and guide entry.
- [ ] 4.2 Implement the `Worktrees` segment: status tags, branch, created, last activity, reason, header with repo and base branch, `Sweep now`, `Refresh`, empty states, and the expanded detail with unmerged commits and uncommitted files; verify decoder tests over the wire fixtures and a render test for the row and detail states.
- [ ] 4.3 Implement the `Report` segment over the `reports` route with the last-sweep summary and removed/kept/failed rows; verify a render test shows the reason for each kept row and an empty state with no reports.
- [ ] 4.4 Implement the Delete action: one click for a safe row, a confirmation naming commits and files plus the Host fingerprint for an unsafe row, a refusal that refreshes the confirmation when the fingerprint changed (including a changed file content), and a list refresh after success; verify tests assert that the confirm request carries `confirm: true` and the fingerprint only after the second click and that a changed fingerprint reopens the confirmation.
